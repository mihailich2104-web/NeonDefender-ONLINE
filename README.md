# Neon Defender (папка проекта: neonoiner) — v2.0.0

## Что нового в v2.0.0
- **LAN-мультиплеер (кооп на 2 игрока, разные компьютеры, без интернета).**
  Меню → **СЕТЕВАЯ ИГРА (LAN)**:
  - **Создать LAN-игру** — этот компьютер становится HOST, поднимает
    TCP-сервер (порт по умолчанию `5000`), показывает свой локальный IP,
    ждёт подключения и запускает матч кнопкой ENTER, когда второй игрок
    подключился.
  - **Подключиться к LAN-игре** — вводите IP и порт компьютера HOST'а и
    жмёте ENTER.
  - Игра полностью авторитетна на стороне HOST (враги, волны, урон, очки
    считает HOST; клиент только шлёт своё направление/выстрел и
    отображает то, что прислал сервер) — 20-30 обновлений/сек по сети,
    рендер остаётся на 60 FPS.
  - На каждом компьютере используются **одни и те же клавиши**: `WASD` +
    `ПРОБЕЛ` — это тот самый игрок, которым управляет этот компьютер.
  - Сетевой код — в отдельном файле `network.py` (`NetworkServer`/
    `NetworkClient` через сокеты + отдельные потоки, чтобы не подвешивать
    Pygame). Одиночная игра и локальный кооп на одном компьютере работают
    как раньше и не требуют сети.
  - **Упрощения этой версии** (сделано осознанно, чтобы сетевой код был
    рабочим и тестируемым, а не превратился в непроверяемую груду
    файлов): нет автопоиска серверов по UDP-broadcast (только ручной ввод
    IP — это и так обязательный запасной вариант по ТЗ), нет счётчика
    пинга в HUD, нет миграции хоста при его отключении (матч у клиента
    корректно завершается сообщением «ХОСТ ОТКЛЮЧИЛСЯ»), нет
    клиент-side prediction — при обычном LAN-пинге (единицы мс) это не
    ощущается, а вот в Wi-Fi с большими помехами локальный игрок на
    клиенте может выглядеть чуть менее отзывчивым.
- **Новые языки**: помимо русского и английского добавлены украинский,
  польский, французский, испанский, итальянский и сербский — выбираются
  в Настройках так же, как раньше (стрелки ◄►), и в установщике Setup.exe
  (мастер Inno Setup теперь предлагает список языков вместо
  единственного русского).



Один файл `game.py` — вся игра. Никаких внешних картинок или звуков: все
текстуры (корабли, выстрелы, взрывы, звёзды, туманности) и звуки рисуются
и синтезируются прямо в коде.

## Что нового в этой версии
- Полноценный игровой цикл (в прошлой сборке `game.py` обрывался на
  конфигах и не запускался — теперь это рабочая игра).
- Локальный кооп на двоих на одном экране: Игрок 1 — WASD + ПРОБЕЛ,
  Игрок 2 — стрелки + ENTER.
- Магазин улучшений (урон, скорострельность, живучесть, скорость) за
  монеты, которые начисляются во время игры.
- Красивое меню с клавиатурной и мышиной навигацией.
- Новая текстура выстрела: маленькая вспышка → вытянутый светящийся
  луч → взрыв-звезда при попадании (как на референсе).
- Более живой космос: градиентное небо, туманности, звёзды с
  параллаксом и мерцанием.
- Три уровня графики (низкая/средняя/высокая), запуск всегда стартует
  на низкой — для совместимости со слабыми ПК; переключить можно в
  настройках. Внутренняя логика отрисовки рассчитана на 60 FPS даже
  на старом железе (кэшированные текстуры, минимум лишних отрисовок
  за кадр).

## Запуск локально (в т.ч. в Termux с X11, для отладки на Android)
```bash
pkg update && pkg upgrade -y
pkg install -y python
pip install -r requirements.txt
python game.py
```
Termux — это ARM Linux, поэтому запустить `.py` тут можно, а собрать через
него нативный Windows `.exe` — нельзя (PyInstaller собирает бинарник под ту
ОС/архитектуру, на которой сам работает).

## Как получить Setup.exe с телефона (реальный рабочий способ)
1. Создайте пустой репозиторий на GitHub (в приложении GitHub или через
   `git` в Termux: `pkg install git`, `git init`, `git remote add origin ...`).
2. Положите в репозиторий содержимое этой папки **целиком** — `game.py`,
   `icon.ico`, `requirements.txt` и папку `.github/workflows/build.yml`
   (уже готова в архиве).
3. Запушьте с телефона:
   ```bash
   git add .
   git commit -m "neon defender"
   git push origin main
   ```
4. На GitHub откройте вкладку **Actions** — сборка стартует автоматически
   на бесплатном windows-runner'е GitHub: соберёт `NeonDefender.exe`
   (PyInstaller) и упакует его в `Setup.exe` (Inno Setup, мастер установки
   на русском языке, современный стиль окна, ярлыки на рабочем столе и в
   меню Пуск — по желанию пользователя).
5. Готовый `Setup.exe` скачивается из результатов запуска (Artifacts →
   `NeonDefender-Setup`).

Это единственный надёжный маршрут «собрать Windows-инсталлятор, управляя
всем с Android/Termux» — сама сборка идёт в облаке, на настоящей
Windows-машине. После сборки на GitHub теперь также лежит готовый
**`NeonDefender-Setup-Zip`** (тот же `Setup.exe`, но уже упакованный в
`.zip` — по вашему запросу).

## Собрать Setup.exe и Setup.zip одной командой (если у вас есть Windows)
Если вы запускаете сборку не через GitHub Actions, а прямо на своём
Windows-компьютере (нужны Python 3.11+ и установленный Inno Setup 6:
https://jrsoftware.org/isdl.php), вот вся сборка одной командой
PowerShell из папки проекта:

```powershell
pip install -r requirements.txt; pyinstaller --onefile --noconsole --name NeonDefender --icon=icon.ico --add-data "fnt_dotumche.ttf;." game.py; & "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss; Compress-Archive -Path "dist_installer\Setup.exe" -DestinationPath "NeonDefender-Setup.zip" -Force
```

(файл `installer.iss` уже лежит в репозитории — это тот же скрипт,
который генерирует и использует `build.yml`; если его нет, возьмите
блок `[Setup]...[Run]` из `.github/workflows/build.yml` и сохраните
как `installer.iss` рядом с `game.py`.) Результат — `Setup.exe` в
`dist_installer\` и `NeonDefender-Setup.zip` рядом с ним.

**Порт по умолчанию для LAN:** `5000` (TCP), задаётся в `network.py`
константой `DEFAULT_PORT` — легко поменять. Для автопоиска игр в лобби
(список созданных игр без ввода IP) дополнительно используется `5001`
(UDP, широковещательные объявления, константа `DISCOVERY_PORT`). Если
Windows Firewall блокирует подключение — при первом запуске HOST-сервера
Windows обычно сама спросит «Разрешить доступ в сети?» (нажмите «Да»);
если подключение всё равно не проходит, откройте порты 5000 (TCP) и 5001
(UDP) вручную: Панель управления → Брандмауэр Windows → Дополнительные
параметры → Правила для входящих подключений → создать правило.

**Radmin VPN:** игра поддерживает игру через Radmin VPN «из коробки» —
объявление лобби и TCP-соединение рассылаются по всем сетевым адаптерам
компьютера, включая виртуальный адаптер Radmin. Требования: Radmin VPN
запущен и подключён к одной и той же сети на обоих компьютерах, и на
хосте разрешён доступ игры к сети в брандмауэре (как для обычной LAN).
Если автопоиск лобби через Radmin всё же не срабатывает (бывает из-за
особенностей маршрутизации широковещательных пакетов в конкретной
версии Radmin) — на экране подключения всегда есть запасной пункт
«ВВЕСТИ IP ВРУЧНУЮ»: хосту нужно посмотреть свой Radmin-адрес (обычно
`26.x.x.x`) в окне программы Radmin VPN и продиктовать его второму
игроку.

## Совместимость
- **Windows 7 SP1 / 10 / 11** — зависимости в `requirements.txt` закреплены
  на версиях `pygame`/`numpy`, которые ещё работают на Windows 7 SP1
  (более новые релизы этих библиотек поддержку Windows 7 не гарантируют).
- **Старое железо** — игра не использует 3D-ускорение/шейдеры, рендер идёт
  через SDL2 (программный или базовый аппаратный рендер), внутреннее
  разрешение фиксировано (1024×640) и масштабируется под размер окна, что
  бережёт слабые видеокарты и процессоры.
- Если на конкретной машине нет звукового устройства (например, в
  виртуалке), игра сама отключает звук и продолжает работать без ошибок.

## Управление
- Игрок 1: `WASD` — движение, `ПРОБЕЛ` — стрельба
- Игрок 2 (режим «Вдвоём»): стрелки — движение, `ENTER` — стрельба
- `F11` — полный экран, `F3` — линии сканирования, `F2` — счётчик FPS,
  `ESC` — пауза/назад

## Что подключено в game.py (версия с расширениями)

В главное меню добавлены пункты **Статистика**, **Новости / обновления** и **Сетевые настройки**;
в меню «Сетевая игра (LAN)» — **Браузер серверов** (LAN + локальные + web-источники, избранное,
недавние). Потеря соединения с хостом открывает экран переподключения. Статистика, достижения и
профиль пишутся после каждого матча. Все старые режимы и экраны сохранены.
Переводы новых экранов лежат в `locales/*.json` и упаковываются в EXE сборкой (`build.yml`).

## Интернет-серверы (ONLINE)

В меню **Сетевая игра → Онлайн-серверы** теперь можно показывать публичные
серверы из центрального каталога через HTTP(S). LAN-автопоиск при этом не
удалён и продолжает работать отдельно.

### Центральный каталог

В архив добавлен `master_server.py`. Он работает без сторонних Python-библиотек:

```bash
python master_server.py --host 0.0.0.0 --port 8080
```

Для игры укажите в `config.json`:

```json
{
  "online_master_enabled": true,
  "online_master_url": "http://YOUR-VPS-IP:8080/api/servers"
}
```

Для публичного сервера также задайте `public_server_host` и пробросьте его
TCP-порт `5000` (или выбранный порт) на VPS/роутере. Сам TCP-протокол игры
не изменён: подключение идёт напрямую к `IP:порт`.

Каталог принимает `POST /api/register`, `POST /api/heartbeat` и
`POST /api/unregister`; формат ответа `/api/servers` совместим с браузером
серверов игры. Это позволяет позже подключить автоматическую регистрацию
хостов, не меняя клиентский интерфейс.
